About this app

{{ brand.name if brand else 'Acme Corp Pipeline Studio' }} is a Databricks App that takes a data request from an analyst to a governed, deployed data product. The analyst describes what they need. The app runs the human steps (the grill, the reuse check, data quality, plan approval and PR review). Genie Code builds the assets, started from a Lakeflow Job. Then the same reviewed artefacts are promoted from dev to staging to prod.

The worked example is request REQ-0142. An FP&A business analyst at Acme Corp asks for a Genie Agent "Margin & Cash" that answers where margin is leaking and what cash is doing, and a dashboard "Margin & Cash Tracker" to track both weekly. Both sit on governed metric views, not on report calculations.

The journey, screen by screen

  1. Home. The analyst's starting point and the recent requests.
  2. The ask (grill). The intake agent pins down who asks the agent, the sample questions, the decisions they drive and the dashboard cadence. It ends with the spec JSON.
  3. What already exists (reuse). Each need is matched against real catalog assets and marked REUSE, EXTEND or GAP, with a coverage %.
  4. Fill the gap with a metric view. The margin-leakage gap becomes a metric view (YAML) that the agent and the dashboard share.
  5. Data quality. Existing rules from the rules repo are listed first. Disabling one needs a reason. Gap rules are proposed, rules on missing columns are rejected, and the review is saved.
  6. Agent and dashboard design. Two short sub-grills: sample questions and benchmark answers, instructions and access for the Genie Agent; pages, KPIs, filters and refresh for the dashboard. PII is refused on shared pages.
  7. Plan and approve (human gate 1). The plan lists each step with its skills. Approve starts the Genie Code job and shows the job run ID.
  8. Build, live. The tracker shows progress per step as Genie Code works: the metric view, the Genie Agent, the dashboard. Each asset gets a link.
  9. PR and AI review (human gate 2). The PR carries the generated definitions (metric view YAML, Genie Agent config, dashboard JSON). The AI reviewer comments on real gaps. A person approves or rejects.
  10. Promote. Approve moves the artefacts from staging to prod and lists the release on Prod Release.
  11. Use it. The analyst asks the Genie Agent the margin and cash questions, and opens the dashboard. The benchmark answers and the dashboard should show the same numbers.

Screens 2 to 7 run on the New request page. Screens 8 and 9 run on the Tracker. Screen 10 is Prod Release. Screen 11 happens in the Genie Agent and the dashboard, outside this app.

The agent roles

Each agent runs on a prompt you can review and edit on Agent config. The roles that apply to a request:

  • Spec Critic challenges the spec for ambiguities before anything is built.
  • Source Profiler reads the source schema and row counts and notes quirks.
  • Pipeline Generator writes the Lakeflow and SDP code and the Unity Catalog metadata.
  • Standards Validator checks the artefacts against engineering standards (PII tags, comments, expectations).
  • Test Generator adds business-rule checks on top of the declared rules.
  • PR Reviewer writes the review comment on the PR, which a person then approves or rejects.
  • Deploy Agent holds the standard operating procedure for the dev and prod deploys.

The App Generator and App Standards Validator are still configurable, but they are not on the Margin & Cash path.

How Genie Code builds

The build is not run by the app's own agents. The app starts a Lakeflow Job (acme-studio-genie-code) with a Genie Code task. The task's prompt names the assets to build and @-mentions the skills (for example metric-view-author, genie-agent-author and aibi-dashboard-standards). The app then polls the run, reads the Genie Code response and records the job run ID against the request, so every build step links to the run that made it.

Status: the job exists in the workspace, but its Genie Code task is still being rehearsed, so it is not yet the live build path. Until it is, a build step that cannot run through Genie Code is created through the Genie and Lakeview APIs from the same reviewed config. That step is labelled as the fallback on the Tracker.

Two human gates

  • Gate 1: approve the plan. Nothing is built until a person approves the plan.
  • Gate 2: approve the PR. Nothing is promoted until a person approves the PR, after the AI review.

Promotion from staging to prod is a release step on Prod Release.

What is real and what is seeded

  • Real. The Acme Corp ERP extracts are files in the raw_erp volume and feed the medallion in vmohan_demo_catalog.cfo_workbench. The reuse matches are real catalog asset IDs. The control tables are in vmohan_demo_catalog.studio_control. The assets a build creates (metric view, Genie Agent, dashboard) are real workspace objects.
  • Scripted. The reuse coverage % is matched against the catalog. It is not a live similarity score.
  • Estimated · demo. The Cost Controls numbers are estimates for the demo, not billing records. The system billing tables settle later.
  • Demo data. The ERP data is synthetic. The example Prod Release comes from a seeded fixture.

Demo reset

Clears the requests, request events and releases in the control schema, closes any open PRs in the pipelines repo (when a GitHub token is set), then re-seeds the example Prod Release. It does not drop the build assets (metric views, Genie Agents, dashboards) or already-merged PRs, and it does not touch the ERP source data.
